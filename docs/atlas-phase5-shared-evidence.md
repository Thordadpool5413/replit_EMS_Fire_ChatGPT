# ATLAS shared evidence on the Replit backend

Reviewed public-source evidence is stored in Replit PostgreSQL, separately from agency profiles and their private notes, contacts, pipeline, source attachments, and drafts. Agency browsing and profile records retain the existing no-sign-in access model. Replit Auth is required only for the reviewed-evidence workspace.

## Access and data boundaries

- The feature is disabled unless `VITE_ATLAS_EVIDENCE_ENABLED=true` and a valid `VITE_ATLAS_EVIDENCE_WORKSPACE_ID` are configured.
- Users sign in through the app's Replit Auth OIDC endpoints. The API checks Replit session identity and an existing `workspace_memberships` role; users cannot grant themselves a role.
- Public-source evidence is published explicitly by an editor and reviewed through append-only decisions. The evidence API is bounded and does not expose private agency notes, contacts, opportunity pipeline, drafts, or attachments.
- New Replit-authored evidence can be reviewed by a different mapped Replit member. A record whose imported author identity is unmapped cannot be approved until an administrator provides an explicit identity mapping. Unmapped historical decisions remain preserved but do not count as valid approval.
- The app does not infer current equipment, purchasing intent, or market share from an evidence record. Evidence does not automatically change agency profiles, scoring, county rollups, or map colors.

## Existing-record migration

The migration script accepts a versioned workspace or collection export. It defaults to dry-run; `--apply` is required for database writes. Imports are additive and transactional. Existing Replit records are never overwritten: identical rows are counted unchanged and conflicting rows are retained in `imported_legacy_records` for review.

Legacy membership, evidence-author, and decision-reviewer identities are not assumed to match Replit Auth user IDs. A role is activated only from an explicit `replitUserId` or an export record explicitly marked with `identityProvider: "replit"`. Evidence and decisions without that mapping are preserved with an unmapped status; approval is blocked until an administrator confirms identity correspondence.

No export has been supplied and no legacy records have been imported yet. The safe next step is to provide the export, inspect the dry-run counts and conflict report, then explicitly approve an additive import. Do not copy or upload credentials with the export.

None of those checks has been represented as production-complete here.

## ATLAS capabilities retained from upstream

- **Evidence review and reconciliation:** Compare published source observations with typed local evidence without promoting the result to agency records, maps, scores, or claims of verified coverage. Incomplete pages, conflicting reads, invalid review history, and unavailable requests fail closed.
- **Review governance:** Keep publication and review roles separate. Decisions are append-only; reviewers cannot approve their own evidence. Challenges, withdrawals, and supersession block older evidence. Corrections use a new observation and an explicitly reviewed replacement chain.
- **Shared opportunity and equipment research:** Reviewed signals remain a bounded, short-lived research sample. The equipment view distinguishes ZOLL, other makers, mixed observations, no eligible observation, unavailable review, and not checked. It does not claim fleet ownership, nationwide market share, or complete county coverage.
- **Public funding and procurement discovery:** Keep source pages, retrieval time, record scope, and uncertainty visible. A discovered award is not available funding, installed equipment, or agency intent; ambiguous and unavailable results are not treated as negative findings.
- **Provider location and directory recovery:** Preserve source listings separately from saved agency records. A location is mapped only from a compatible, source-backed identity and address match; uncertain, conflicting, historical, or missing addresses remain unassigned rather than receiving guessed coordinates or county assignments. Public registry search remains available independently of saved-account requests.
- **End-user validation:** Imported and source-derived facts remain research references until the end user reviews the individual fact and its source. Missing information remains unknown; completing a task or seeing a registry listing does not validate agency information.

These notes retain the applicable upstream Phase 5 behavior while replacing its obsolete cloud provisioning instructions with the Replit access and storage model above. The complete upstream text remains available in Git history.

Only independently approved, currently unblocked, reconciled observations produce research signals. Pending and challenged/withdrawn observations remain contextual blockers so newer negative evidence cannot resurrect older opportunities. Equivalent duplicate observations require approval of all active published copies. Superseded originals are omitted only when their matching correction chain ends at an approved, unblocked document; broken/cyclic/missing chains suppress the account's entire review. Local facts and notes are deliberately excluded from this shared-only calculation. The engine uses existing freshness rules, a 365-day upcoming contract horizon and documented procurement dates. It withholds ambiguous same-number solicitations from different issuers, mixed vendor values and unknown equipment brands. Signals provide source, reviewer, published document date and next verification action. No scores, forecasts, market share or pipeline value are manufactured.

The shared Radar remains isolated from the existing local Radar, competitive equipment map and operational agency records. Access remains behind the existing Replit feature flag. Production activation, end-to-end device testing, larger-account pagination and territory-wide coverage need separate validation. No production Replit configuration, records, or data were changed.

## Phase 5.1F — reviewed competitive equipment mapping
The GIS territory workspace and Google Maps workspace expose an explicit reviewed equipment map entry when the separate evidence feature is enabled. It reuses the authenticated member gate, source-reviewed Radar validation and bundled Census county outlines; it does not inject private shared observations into normal map data, saved agency records, exports, or local scoring. A user selects one state and at most five unique source-native accounts and starts a server check. Each account uses the bounded two-pass decision review (fewer than 50 records); server failures and incomplete review are unavailable, not unknown or competitor. Membership is checked before and after the sample. Results are memory-only, scoped to the selected identity fingerprints and expire five minutes after sampling starts; offline events invalidate them.

Reviewed equipment observations use the same independent approval, correction-chain, conflict, duplicate and freshness gates as the shared Radar, including recognized ZOLL observations. Multi-vendor strings and unknown makers do not produce positive classifications. Product categories can be filtered without additional server reads. Map colors distinguish ZOLL observed, other maker observed, both observed in the sample, no eligible recognized observation, review unavailable and not checked. County color is not a fleet statement or market share. Mixed may reflect different agencies or categories. Unmapped records are retained in the selected-account list; only a source-native county FIPS that matches a single reference county in the same state and does not conflict with the saved county or headquarters state can be plotted. No coordinates, name guesses, city centroids or service-area fan-out are used. Boundary loading failure withholds shapes rather than inventing assignments.

This is a deliberately limited research sample, not a nationwide completed census or an all-county bulk backfill. No shared results are persisted or copied to the existing equipment map. Live Replit authentication, devices, source coverage, larger account pagination and bulk discovery remain outstanding. Production configuration and data are unchanged.

The dedicated national provider address backfill workflow is triggered only by an explicit push to atlas/national-location-backfill (or a dispatch on that branch). It streams the pinned official November 9, 2026 V2 NPPES dissemination archive and matches existing Type 2 ambulance organization records by exact NPI plus normalized legal name, state, city and ZIP. No bulk live NPI API requests, mailing address fallback, individual records, or county/name-only identity association. USFA HQ and Florida in-state EMS license records use existing official bundled sources. Excluded IDs, historical records, missing addresses, conflicting records, no matches and source failures are counted independently. Census geographies batch service uses up to 4,000 public street addresses per batch, exact match and compatible street/city/state/ZIP, finite coordinates and current county FIPS; coordinates are approximate TIGER ranges. The workflow publishes a separate review branch with public state-sharded assets only, first for source addresses then with geocoding. It never pushes main or mutates production data. Coverage, release SHA, shard hashes, native keys and status totals are checked before publication; generated branch requires separate PR and CI. The public snapshot is bound to the exact source directory shard hashes. Individual provider profiles prefer a linked recorded address or matching bundled source identity, and the saved account map can use validated bundled coordinates without manual lookup. The directory can display Census-matched address county where the base source omitted it; original county assertions are not overwritten. A separate opt-in teal marker layer displays up to 150 mapped public registry listings per page in a selected state/county/city, independently of saved accounts, equipment, opportunity scores and operational verification. The result is not an exhaustive operating-station inventory. Ohio state agency codes lack street addresses in the current roster; no fabricated address is inferred. If an address or county conflicts, withhold the corresponding mapping/assignment rather than overwrite an authoritative source. No production deployment is implied by this pipeline.

### Provider location completeness follow-up
Every displayed national registry listing now has a location outcome, including missing FDID, historical, missing/nonphysical address, pending or unavailable geocoder, no exact match, conflicting source/county and mapped street. Point placement is not proof of an operating EMS/fire station or a rooftop guarantee; parcel/property access and site locations are explicitly labeled. ## Phase 5.7A — source-only provider records and end-user validation
The previous implementation generated provider records from county and city geography and loaded illustrative hardcoded provider profiles into the initial saved directory. Both production initialization paths are retired. Geographic queries return only existing eligible accounts; no fallback provider creation when a place/category is missing. Historic synthetic/illustrative ID prefixes and origin markers are quarantined even when synced or associated with registry identities; an identity association never verifies historic equipment or metrics. Existing local deltas and legacy user work remain preserved for explicit export/reconciliation; pending legacy mutations are retained with a review-required error rather than uploaded. No cloud deletion, automatic migration, or reassignment is performed. Public registry listings remain separately accessible and new accounts require explicit source review. The existing legacy seed source modules are retained for history but not imported by the initial production directory. Imported source facts must still be individually validated by the end user: explicit review basis, named reviewer, method, time, field/current value, and source record ID/name/URL/kind/period. A source or value change invalidates the current confirmation status; no automatic whole-profile validation. Unknown fields remain unknown. Test fixtures are injected only by loopback browser QA, not bundled in production. This is provider-origin and review hardening, not a certification of every historic financial/clinical benchmark or every stored manual record. Review pending changes, CI and live deployment before release.

## Production search recovery
The source-only policy retired synthetic seed accounts, exposing the old agency queue's dependency on Firestore saved-account reads. That queue treated failed cloud reads as the whole provider search failing even while the bundled public registry was independent. The agency directory now searches actual public source listings with the same query, state, county, ZIP and category controls, without needing saved accounts or a cloud connection. Nationwide name/city/ZIP/ID queries load state shards in four bounded workers; selected-state queries also enrich street addresses and county assignments using the checksum-verified location snapshot. A partial data request is explicitly identified, not presented as an empty nationwide result. Provider detail is read-only until the end user explicitly creates or links an account. The legacy saved workspace retains its own status and retry control; this change does not establish an authenticated Replit workspace persistence migration. Failed location manifests are retryable and registry fetches revalidate their cache. Browser acceptance checks block legacy cloud domains and require a real public Florida source result and read-only provider profile without creating an account. Test fixtures remain isolated. No live data is modified.
