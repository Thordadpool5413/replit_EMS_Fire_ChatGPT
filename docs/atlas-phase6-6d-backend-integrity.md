# Phase 6.6D — Agency persistence integrity and query efficiency

Code inspection found a receipt replay defect: a later canonical payload was returned with the original receipt revision written into the embedded agency. Keep the immutable top-level receipt revision (existing API contract) and label the returned canonical agency with its real revision. Receipt replay now uses the existing mutation-ID transaction lock, then agency lock and a single canonical read; remove redundant receipt lookup. Fail closed on missing/regressed canonical records. Existing role checks, revision conflicts and quarantine rules unchanged. Replace up to 25 sequential batch inserts with one atomic multi-row insert in stable ID order, retaining original caller order of created IDs and conflict-do-nothing semantics. Empty batches return immediately. PostgreSQL integration tests cover replay after newer save, concurrent identical retries, cross-agency receipt conflict, mixed existing/new batches, empty and repeated batches. No database migration or production data writes. Query savings are structural, not measured production latency. Live database profiling, directory-loading and synchronization stress tests remain future work; user controls Replit deployment.
