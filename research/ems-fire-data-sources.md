# Data Sources That Can Make EMS & Fire Territory Intelligence Better

**Research date:** November 1, 2026  
**Scope:** U.S. national and state APIs, public datasets, and the current Google Maps MCP connection; Florida is treated as the first state in a nationwide rollout.  
**Purpose:** Identify which sources can improve agency records, what they can actually prove, and what still requires an agency's own records.

## Executive summary

The app's biggest opportunity is not another API key. The current code audit found live CMS NPPES identity lookups and OpenFEMA fire-grant records; Google Maps supports mapping, not EMS fact verification. The strongest new national sources are USFA's department registry and NERIS public layers for fire-department identity, boundaries, and stations; CMS provider/service files for historical Medicare billing activity; CMS hospital records and the FCC PSAP registry for facility and dispatch context; and Census/CDC sources for clearly labeled population-health context. [[1](https://apps.usfa.fema.gov/registry/download)] [[2](https://www.usfa.fema.gov/neris/public/)] [[3](https://services5.arcgis.com/lPbcyJOcoLyZmvo6/arcgis/rest/services/NERIS%20Public%20Fire%20Departments/FeatureServer/1?f=pjson)] [[4](https://npiregistry.cms.hhs.gov/api-page)] [[5](https://data.cms.gov/provider-summary-by-type-of-service/medicare-physician-other-practitioners/medicare-physician-other-practitioners-by-provider-and-service)] [[6](https://data.cms.gov/provider-data/dataset/xubh-q36u)] [[7](https://www.fcc.gov/general/9-1-1-master-psap-registry)] [[8](https://www.census.gov/geographies/mapping-files/time-series/geo/tiger-line-file.html)] [[9](https://www.cdc.gov/places/about/)]

These sources do **not** create a national, public record of current EMS call volume, individual provider claim denials, current apparatus inventories, CAD/ePCR deployments, receiving-hospital relationships, or current vendor contracts. NEMSIS public releases remove agency identifiers; Florida EMSTARS patient records are confidential; CMS's public measures have different scopes; and awards are not proof of installed equipment. For those facts, the strongest path is an agency-supplied, authorized report or local procurement record, displayed with its exact period, scope, source, and match basis. [[10](https://nemsis.org/using-ems-data/request-research-data)] [[11](https://www.floridahealth.gov/statistics-data/emergency-medical-services-ems-data-systems/ems-data-reports-research)] [[12](https://data.cms.gov/summary-statistics-on-use-and-payments/physiciansupplier-procedure-summary)] [[13](https://www.cms.gov/files/document/medicare-ground-ambulance-data-collection-system-gadcs-report-appendix-year-1-year-4-cohort-analysis.pdf)] [[14](https://www.fema.gov/openfema-data-page/non-disaster-and-assistance-firefighter-grants-v1)] [[15](https://api.usaspending.gov/docs/endpoints)]

The recommended order is: build a real agency/station identity layer from USFA and NERIS; add CMS Medicare utilization and properly labeled sector benchmarks; build Florida's license, EMSTARS, and trauma-source lane; then add hospital/PSAP, procurement, and Census/CDC context. Keep estimates and generated hypotheses visible for user review, but label them separately from source-reported facts.

## What is connected now

The project's existing data-source map reports that NPPES is used for provider identity checks and OpenFEMA AFG for grant records. The Google Maps JavaScript API renders maps, while the configured Google Maps Platform MCP exposes documentation/instruction retrieval tools—not a live Places, Geocoding, or Routes feed into agency records. The existing app source map also identifies generated or modeled values for some leadership, fleet, vendors, call volumes, hospitals, and opportunity estimates. These should remain visible if useful, but the display should identify them as generated hypotheses and show their inputs/formula rather than presenting them as observed agency facts.

Most public-government sources below offer a public API or downloadable file, so this research did not identify a need for new private API credentials. Google Maps Platform calls are separate and would use the existing Maps key if the additional services are enabled. The main work is source ingestion, entity matching, refresh handling, and field-level provenance—not collecting more credentials.

## Key findings

### 1. USFA and NERIS can substantially improve fire-agency and station records

USFA's National Fire Department Registry provides department IDs, names, headquarters and mailing addresses, county, phone, website, organization type, reported station count, staffing fields, and national/state CSV downloads. USFA also publishes a station-address file for departments that supplied station information. One important join rule: states assign FDIDs, so the same FDID can occur in more than one state; store it as **state + FDID**, not as a globally unique ID. [[1](https://apps.usfa.fema.gov/registry/download)]

NERIS adds a useful, more current location layer. Its public department/station feature layers include NERIS identifiers, department-to-station relationships, station names and addresses, unit count, point geometry, and export/update metadata. The reviewed department schema did not expose a direct FDID crosswalk. Keep USFA IDs and NERIS IDs as separate identifiers until a verified crosswalk or an explicit match is available; name-and-city similarity should create a candidate match, not silently merge records. [[2](https://www.usfa.fema.gov/neris/public/)] [[3](https://services5.arcgis.com/lPbcyJOcoLyZmvo6/arcgis/rest/services/NERIS%20Public%20Fire%20Departments/FeatureServer/1?f=pjson)] [[16](https://services5.arcgis.com/lPbcyJOcoLyZmvo6/arcgis/rest/services/NERIS%20Public%20Fire%20Departments/FeatureServer/0?f=pjson)]

NERIS incident data can add a measure of **reported fire-service incidents**, but it is not EMS call or transport volume. There is also a freshness discrepancy: the USFA public-data table lists a 60-day incident lag, while a newer launch article describes updates multiple times per week. Capture the layer's own `dataLastEditDate` and incident date on each refresh, and do not show a fixed freshness promise until the live layer confirms it. [[2](https://www.usfa.fema.gov/neris/public/)] [[17](https://www.usfa.fema.gov/blog/neris-public-transparent-fire-incident-data)] [[16](https://services5.arcgis.com/lPbcyJOcoLyZmvo6/arcgis/rest/services/NERIS%20Public%20Fire%20Departments/FeatureServer/0?f=pjson)]

NPPES remains useful for a separate identity link: its read-only API is updated daily and supports NPI, entity type, organization name, taxonomy, and address searches. CMS explicitly says that NPI issuance does not verify licensure or credentialing. Treat a Type 2 NPI as a billing/provider identity candidate—not as proof that the organization is the operating department, has a particular chief, or owns a station. [[4](https://npiregistry.cms.hhs.gov/api-page)]

### 2. Public NEMSIS data cannot verify an individual EMS agency; Florida has a better but restricted route

The 2025 NEMSIS public-release research dataset is large, but it removes the identities of the EMS agency, receiving hospital, and reporting state. NEMSIS public dashboards are aggregated for high-level inquiry and trending, and state submissions and data definitions vary. That makes these products useful for national context and clinical measure definitions, but not for matching an individual app profile to its exact annual calls, acuity, or receiving hospitals. [[10](https://nemsis.org/using-ems-data/request-research-data)] [[18](https://nemsis.org/view-reports/public-reports/version-3-public-dashboards)] [[19](https://nemsis.org/wp-content/uploads/2025/09/NEMSIS-End-of-Year-Report-2024-9-24-25.pdf)]

Florida's EMSTARS program is more directly relevant to an agency-level record. Florida DOH says licensed EMS providers can review their own standardized QA and operational reports, while incident-level patient records submitted to the state are confidential. The department publishes statewide aggregated reports and accepts data-use requests; its public dashboard page currently lists workforce and data-quality dashboards. A public EMSTARS aggregate portal also exists, but this research fetch exposed only a welcome page, not enough to confirm available measures, filters, or agency granularity. Validate that portal before relying on it as a feed. [[11](https://www.floridahealth.gov/statistics-data/emergency-medical-services-ems-data-systems/ems-data-reports-research)] [[20](https://www.floridaemstars.com/public-dashboards.htm)] [[21](https://emsaggregate.floridahealth.gov/)]

For Florida, the linked statewide licensed-provider PDF is not a dependable current roster: its embedded processing date is October 23, 2020, despite a newer-looking upload path. The state licensing page and individual license verification are better leads, but a stable bulk API was not established in this research. Florida DOH also provides a trauma-center listing and map; that supports a state-designated trauma capability, not an EMS agency's current destination agreement or STEMI/cath-lab capability. [[22](https://www.floridahealth.gov/licensing-regulations/emergency-medical-services-system/ems-service-provider)] [[23](https://www.floridahealth.gov/wp-content/uploads/2025/08/ems-providers.pdf)] [[24](https://www.floridahealth.gov/licensing-regulations/trauma-system)]

**Best path for actual EMS volume:** let an authorized agency provide an aggregate CAD/ePCR/EMSTARS export. Keep separate fields for calls received, dispatched incidents, patient contacts, and transports; define the reporting period and service area; and display the exact report/source record. Do not label fire incidents, population estimates, or Medicare service units as total EMS emergency volume.

### 3. CMS can add Medicare utilization and benchmarks, but not the requested provider/county claim-denial rate

CMS's “Physician & Other Practitioners by Provider and Service” dataset is the most useful public provider-level addition for historical Medicare activity. It organizes use, payments, and submitted charges by NPI, HCPCS, and place of service and is typically updated annually. For ambulance HCPCS, it could support a clearly scoped **Medicare billed-service count by billing NPI and year**. It is not all-payer activity, total dispatches, unique emergency calls, or pickup-county volume. [[5](https://data.cms.gov/provider-summary-by-type-of-service/medicare-physician-other-practitioners/medicare-physician-other-practitioners-by-provider-and-service)]

CMS's Physician/Supplier Procedure Summary (PSPS) is a different product. Its published summary and file layout describe submitted and denied service counts and denied charges by procedure and carrier/pricing locality. The layout reviewed here is dated 2015, so its exact fields must be checked against the current downloadable release before implementation. If the current file confirms matching denominators, the app could offer a separate **Medicare ambulance denied-service share** by carrier locality, ambulance HCPCS, and reporting year: `denied services ÷ submitted services × 100`. That is a service-count ratio, not a count of unique denied claims; PSPS does not supply the provider NPI and pickup-county FIPS needed for a provider or county claim-denial rate. [[12](https://data.cms.gov/summary-statistics-on-use-and-payments/physiciansupplier-procedure-summary)] [[25](https://www.cms.gov/research-statistics-data-and-systems/files-for-order/nonidentifiabledatafiles/downloads/pspsrecordlayoutaugust2010.pdf)] [[26](https://www.cms.gov/data-research/cms-data/limited-data-set-lds-files/physician/supplier-procedure-summary-psps)] [[27](https://data.cms.gov/resources/physician-supplier-procedure-summary-methodology)]

CMS provider/service use, PSPS service counts, and CMS Geographic Variation must remain separate metrics. Geographic Variation supplies Medicare use/spending comparisons by state and county, not ambulance denial counts. CMS's Ground Ambulance Data Collection System (GADCS) is valuable for **peer benchmarks**: its public Year 1–4 cohort report covers data reported through May 15, 2025 and summarizes selected organizations' service volume/mix, response times, vehicle/equipment costs, and other operating measures. It is a sampled, aggregated benchmark—not a public row for every provider or current fleet. [[28](https://data.cms.gov/summary-statistics-on-use-and-payments/medicare-geographic-comparisons/medicare-geographic-variation-by-national-state-county)] [[29](https://www.cms.gov/medicare/medicare-fee-for-service-payment/ambulancefeeschedule/downloads/medicare-ground-ambulance-faqs.pdf)] [[13](https://www.cms.gov/files/document/medicare-ground-ambulance-data-collection-system-gadcs-report-appendix-year-1-year-4-cohort-analysis.pdf)]

For an actual provider or pickup-county claim-denial rate, the defensible calculation still requires matching aggregate counts from an authorized billing/remittance report. Use the same claim unit, payer/product, denial definition, adjudication stage, and period in numerator and denominator; assign the county by **pickup/service county FIPS**, not provider headquarters. Calculate `100 × denied unique final claims ÷ adjudicated unique claims`. For a state, sum compatible county counts first and divide; do not average percentages. Keep denial-dollar amounts separate from claim counts. If the app's no-sign-in choice remains, imported summaries should stay browser-local rather than being described as workspace-shared.

### 4. Hospital and 911 sources help with location context, not operational relationships

CMS Hospital General Information is a current nationwide list of hospitals registered with Medicare, with facility ID, name, address, phone, type, ownership, and an “Emergency Services” field. It is a good base for locating those hospitals, but that field does not establish current 24/7 emergency capacity, cath-lab availability, STEMI designation, trauma level, ambulance acceptance, or an agency's actual transport destination. State-designated trauma lists can add capability where available; hospital destination relationships still need an agency protocol or verified transport data. [[6](https://data.cms.gov/provider-data/dataset/xubh-q36u)] [[24](https://www.floridahealth.gov/licensing-regulations/trauma-system)]

The FCC's Master PSAP Registry provides an FCC-assigned PSAP ID, name, state, county, city, change information, and per-record modification date through public spreadsheet downloads. It does not provide the dispatch jurisdiction polygons or identify an agency's CAD/ePCR vendor. CAD/ePCR and maintenance suppliers are best sourced from an awarded local contract, active agreement, or agency-provided record—not a search result or vendor customer list. A local RFP proves a procurement was solicited, not that a vendor was selected or remains deployed. [[7](https://www.fcc.gov/general/9-1-1-master-psap-registry)] [[30](https://www.losalamosnm.gov/Government/Departments-offices/Administrative-Services-Department/Procurement/RFP24-56-CAD-Mobile-RMS-JMS-CMRJ-INTEGRATED-PUBLIC-SAFETY-SYSTEM)]

### 5. Grants, federal awards, Census, and CDC can add useful context—but not a live asset inventory

OpenFEMA AFG is already integrated. Its annual award records include award number, fiscal year, award amount, and a `vendorName` field that FEMA defines as the award recipient/grantee—not necessarily an equipment vendor. FEMA notes that award amounts can change through closeout and that a state-associated amount does not always mean the state itself received the funds. Use awards as historical funding and purchase leads, not proof of a specific vehicle or device currently in service. USAspending and SAM.gov add federal award/contract searches; they do not provide a comprehensive state/local purchasing feed. The federal sources reviewed here do not form a complete local procurement directory; local RFP records can show solicitations but not prove selection or current deployment. An award or solicitation should be matched to the buyer, contract/award number, vendor, item, effective term, and closeout before the app labels a current supplier or asset. [[14](https://www.fema.gov/openfema-data-page/non-disaster-and-assistance-firefighter-grants-v1)] [[15](https://api.usaspending.gov/docs/endpoints)] [[31](https://sam.gov/contract-data)] [[30](https://www.losalamosnm.gov/Government/Departments-offices/Administrative-Services-Department/Procurement/RFP24-56-CAD-Mobile-RMS-JMS-CMRJ-INTEGRATED-PUBLIC-SAFETY-SYSTEM)]

For the GIS layer, 2026 TIGER/Line files provide current boundary geometry and geographic codes, while the 2025 ACS release adds recent state-level demographic estimates; ACS 5-year data supports smaller geographies such as counties, tracts, and ZIP Code Tabulation Areas (ZCTAs). Do not treat a ZCTA as an exact USPS ZIP boundary. CDC PLACES provides modeled health estimates across counties, tracts, places, and ZCTAs; the latest SVI available in this research is based on 2022 ACS data. These layers can help explain population risk and territory context, but they are not ambulance demand, actual clinical acuity, or an agency's calls. [[8](https://www.census.gov/geographies/mapping-files/time-series/geo/tiger-line-file.html)] [[32](https://www.census.gov/programs-surveys/acs/news/updates.html)] [[33](https://www.census.gov/data/developers/data-sets/acs-5year.html)] [[9](https://www.cdc.gov/places/about/)] [[34](https://www.atsdr.cdc.gov/place-health/php/svi/svi-data-documentation-download.html)]

### 6. Use Google Maps for geospatial assistance; do not treat its MCP as an agency-data source

The existing Google Maps Platform MCP in this workspace is a documentation/instructions MCP. It is not a runtime place-search or routing connector. If the app needs map assistance, Places API (New) can help locate candidate stations and hospitals, Geocoding can position a verified address, and Routes API can estimate station-to-hospital distance/time. Those are candidate/location and route estimates; they cannot confirm that a facility is the agency's station, that the agency transports there, or that the route reflects ambulance dispatch, local protocols, access points, or real response performance. Data-driven boundary styling can visualize the app's own state/county values; the app still has to supply the metric, period, source, missing/zero distinction, and join. [[35](https://developers.google.com/maps/documentation/places/web-service/overview)] [[36](https://developers.google.com/maps/documentation/geocoding/overview)] [[37](https://developers.google.com/maps/documentation/routes)] [[38](https://developers.google.com/maps/documentation/javascript/dds-boundaries/overview)]

## Recommended build order

| Priority | Add or improve | Why it matters | Keep the metric labeled as |
|---|---|---|---|
| 1 | USFA registry + NERIS department/station layers; maintain a crosswalk of state+FDID, NERIS ID, and NPI | Replaces generated fire identities/locations with public source records and creates a real station map | Registry-reported department/station details; show source date and match basis |
| 2 | CMS provider/service history + GADCS peer benchmarks; validate current PSPS schema | Adds real historical Medicare service activity and sector operating benchmarks without confusing them with total response volume | Medicare billed services by NPI/year; benchmark cohort; optional service-unit denial share |
| 3 | Florida license, EMSTARS, and trauma lane | Starts the state-by-state rollout with a real license source, agency-only operational reports, statewide aggregates, and trauma designations | License record, agency-supplied report, state aggregate, or trauma designation—each separate |
| 4 | CMS hospitals + FCC PSAP registry + state STEMI/trauma and procurement records | Improves facility/communications context and exposes actual local records where available | Facility/PSAP directory record or specific contract; never infer transport/vendor relationship |
| 5 | Census ACS/TIGER + CDC PLACES/SVI layers | Makes the GIS view more useful without inventing agency operational data | Population/health context with geography and data vintage |

Across every phase, store evidence per fact: source URL and source record ID, retrieval date, reporting/effective period, source-specific agency identifier, match method/confidence, and whether the value is reported, user-imported, derived, estimated, or generated. Keep missing distinct from zero. This lets users see and challenge available information without presenting every populated field as an official current fact.

## Limitations

This is a research snapshot from November 1, 2026, not a guarantee that every endpoint will remain stable. NERIS documentation differs on incident freshness; check its live layer timestamps. CMS's PSPS record layout fetched here is from 2015, so validate the current dataset schema and suppression rules before showing any derived percentage. Florida's public EMS aggregate portal did not expose its underlying measures in the research fetch, and the statewide provider roster is stale. A source catalog or award list is not evidence that a source is connected to the app or that a piece of equipment is currently installed.
