# Phase 9.0K: Texas state organization registry expansion

Official Texas DSHS open records page publishes separate monthly EMS provider agencies and first responder organization rosters. Both direct workbook URLs were confirmed on the official page on November 25, 2026. Provider licenses and FRO registrations must remain distinct identities. Existing parser preserves text IDs and now supports numeric cells only when the workbook explicitly declares a fixed all-zero display format; unformatted numeric identifiers remain blocked. Source address column semantics and workbook SHA-256 are retained; mailing addresses are never treated as operational locations. Only organization-level allowlisted fields are emitted. Missing or ambiguous schema fails closed and produces schema-only diagnostics. Separate CI acquisitions prevent one roster's failure from concealing the other. Source status is informational, not live licensing verification. No bundled roster updates or map pins; all records require end-user validation. Current public state roster files remain FL and OH until Texas candidate review and integration.

Source: https://www.dshs.texas.gov/dshs-ems-trauma-systems/open-records-requests

Live schema correction: Both downloaded files expose the same exact 21-column header at row 2, including `Primary Name`, `DBA Name`, `Mailing Address 1/2`, `First Licensure Date`, and `Station Count`. Production parsing requires the complete observed schema. Preserve the primary and alternate names separately, original identifier column label, status/rank/date, mailing address semantics, and source-reported aggregate station count. Do not retain phone/email, infer service-level equivalence, convert mailing addresses into headquarters, or create station records from aggregate counts. All outputs remain review-only. Workbook size includes header/title rows; actual organization totals come from validated parsed rows.

The first-responder live run parsed 643 rows successfully. The provider workbook exposed at least one contradictory first-licensure/expiration pair. The exact reviewed schema now retains both source values and an explicit `licenseDateConflict` marker; it never rewrites the values, claims current eligibility, or discards the rest of the valid roster. Generic schemas continue rejecting reversed dates. Conflict counts are emitted in the acquisition log and candidate metadata.
