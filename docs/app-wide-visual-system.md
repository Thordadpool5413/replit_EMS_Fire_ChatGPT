# App-wide visual system

This pass changes the shared application presentation rather than just profiles.

- One route-to-icon registry is consumed by desktop navigation, mobile navigation, all secondary workspace tabs, report/settings destinations, and tool headings. Symbols use 1.8-pixel outline strokes; labels remain visible. Topic symbols do not certify source verification or performance.
- Shared headings establish a clear title, supporting text and restrained navy/teal subject badge. Agency directory and Field Work use the same heading component as Reports and Settings.
- Persistent navigation uses a navy brand area, compact rows, and a teal/navy selected state. Mobile navigation uses the same symbols and a selected marker.
- Reports and Settings have recognizable destination icons, compact surface treatments, clear export panels, and navigation before long data-management sections.
- Purchasing, grants, clinical reference, federal sources, backups, data health and registry/import sections use the same subject symbols.
- Shared typography, canvas, borders, shadows, table headings/hover states, focus indicators and mobile form sizes are coordinated. Unused Inter and Geist font downloads are removed; Instrument Sans and Manrope remain.
- National/state/county map frames share the navy palette without changing geographic layers, legend semantics, or source risk colors. County reference rows have a compact title/value hierarchy.
- Existing profile identity and discovery controls remain in place. Icons stay decorative when paired with text; no new data is invented for presentation.

Checks: workspace type checks, unit suite, style ownership, production build, and built-module validation. Automated checks do not establish visual fidelity. Browser rendering, physical-device layout, and installation still need verification; the environment's Chromium audit has been unable to start. No claim is made that every screen has passed visual QA.
