# Phase 6.6F — Shared working pipeline

One server-backed working opportunity per unique saved source-native provider, separate from public evidence and existing CRM stage. Existing private agency workspace viewer/editor rules govern access; no new manager privilege or individual assignment. GET/PUT require the canonical saved identity and withhold duplicate or changed identity bindings. Server validates explicit confirmation, stage requirements, bounded fields and optimistic revisions; PostgreSQL transaction records an immutable revision with the authenticated actor. UI reads shared records on entering the pipeline, leadership, coaching and analytics views, with explicit reload. Browser-local records are retained; a user may copy one into a new shared draft only when no shared record exists, then explicitly validate and save. No automatic import or history fabrication. A failed or ambiguous save requires reload; no automatic offline write queue. 

Deployment: back up the database, review additive schema changes, and run `pnpm --filter @workspace/db run push` in Replit against the intended database before deploying the updated application. Do not use push-force in production. Existing pipeline rows are not migrated automatically. Shared access is the current single agency workspace, not team-level territory isolation or multi-opportunity support. User controls Replit deployment. CI uses disposable PostgreSQL only; production migration, authenticated live testing and cross-device acceptance remain required.
